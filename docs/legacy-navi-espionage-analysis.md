# 옛 NAVI 첩보 코드 분석

분석 기준은 `LCW_RE-RE`의 `archive/final-shutdown` 브랜치, 커밋
`89a16c095f68d75b0ad7548425652134fbc8ea32`이다. 문서 설명이 아니라 실제
Python과 SQLite migration을 기준으로 확인했다.

## 실제로 구현되어 있던 사용자 기능

- `/첩보`: 자기 국가의 `intelligence_agencies` 한 행을 읽어 첩보력,
  방첩력, 작전 슬롯, 경보 단계를 Embed와 고정 이미지로 보여준다.
- `/국가운영` 현황판의 첩보 버튼: 동일한 기관 수치와 진행 중 작전 수를
  조회한다.
- 국가 전용 게시물 생성기: 기관 현황과 작전 목록을 텍스트로 렌더링한다.
  작전 결과가 DB에 이미 있으면 성공, 발각, 귀속 여부까지 표시한다.

사용자가 대상·임무 종류·투입량을 입력하는 Slash Command, 관리자가 성공 여부를
판정하는 Discord UI, 난수 판정기, 국가 효과 적용 코드는 실제 아카이브에서 찾지
못했다. 따라서 옛 시스템은 스키마와 조회/게시 UI까지 구현됐고, 임무 생성·진행·판정
흐름은 미완성으로 보는 것이 정확하다.

## 저장 구조

| 테이블 | 주요 값 | 확인된 용도 |
| --- | --- | --- |
| `intelligence_agencies` | 국가별 첩보력, 방첩력, 슬롯, 경보 | `/첩보`와 현황판 조회 |
| `spy_networks` | 소유국, 대상국, 분야, 침투도, 재사용 대기 | 스키마만 존재 |
| `intelligence_operations` | 소유국, 대상국, 작전 종류·단계·상태, 성공·발각·귀속, 시작·종료 시점 | 게시물 조회와 결과 표시 |
| `intelligence_snapshots` | 대상, 분야, 신뢰도, 취득·만료 시점, JSON 스냅샷 | 스키마만 존재 |

연결 키는 옛 SQLite의 `guild_id`와 `country_id`였다. 이는 TLR의 정본 국가 식별자가
아니므로 이식 대상이 아니다. 확인된 코드에는 첩보 결과가 GDP, 연구력, 안정도 같은
국가 효과를 직접 바꾸는 처리도 없다.

## 버릴 부분

- 옛 국가 ID, 길드 ID, 국가 채널·스레드 매핑
- 기존 SQLite의 기관·네트워크·작전·스냅샷 값
- `intelligence_enabled` 기능 플래그와 옛 대시보드 이미지에 묶인 Discord UI
- NAVI가 첩보 임무를 직접 생성하거나 판정하는 구조

NEW NAVI에는 위 테이블이나 `/첩보` 명령을 만들지 않았다.

## TLR 「첩보 임무」에 재사용할 개념

- 문자열 국명이 아니라 안정적인 소유국·대상국 ID 사용
- 임무 종류, 준비/진행/종료 단계, 상태를 분리한 상태 머신
- 국가별 동시 작전 슬롯과 대상·분야별 네트워크
- 침투도와 재사용 대기시간
- 성공 여부와 발각 여부, 배후 귀속 여부를 서로 다른 결과로 기록
- 신뢰도와 만료 시점을 가진 정보 스냅샷
- 사용자 제출과 관리자 판정을 분리하고 모든 변경을 감사 로그로 기록

사이트 구현 시에는 이 개념만 참고하고 TLR 인증, 국가 소유권, 세계시간, RLS 정책을
기준으로 새 모델을 설계해야 한다. 향후 NAVI가 맡을 수 있는 범위는 임무 완료·새 보고서
도착 알림뿐이며, 임무 작성·판정 UI는 사이트에 두는 것이 현재 경계와 맞다.
